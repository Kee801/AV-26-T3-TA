information required: Byte order, Bit start, Bit length, Offset, Scale
We use a dbc file to decode raw CAN bus data to physical values.

UNDERSTANDING DBC DATA

BO_ defines a CAN message
SG_ defines a signal inside the CAN message


example: SG_ MeasuredAngle : 0|16@1- (0.1,0) [0|0] "deg" Vector__XXX
start bit = 0
signal length = 16 bits
endianness = 1 / 0
signedness = - / +
(0.1, 0) means physical_value = raw_value x 0.1 + 0

ENDIANNESS:
if endianness is 1, it is little-endian where the lower order byte comes first
                 0, it is Motorola where the higher order byte comes first 

SIGNDNESS:
if +  it is unsigned, if - it is signed
UNDERSTANDING CAN DATA

format of the data is candump

example: (1705638751.000000) vcan0 200#00001400852FB01D
(1705638751.000000) - this is timestamp
vcan0 - interface 
200#00001400852FB01D - CAN frame
0x200 - CAN ID
00001400852FB01D - CAN data

BIT NUMBERING
00001400852FB01D - 00 00 14 00 85 2F B0 1D
convert each byte to bits and then reverse number.
example: 14 - 0  0  0  1  0  1  0  0
              23 22 21 20 19 18 17 16 

USING MANUAL SHIFTING CASE SIGNAL BIT

Case 1: Start 0, length 16 -> it will occupy bits 0 to 15 which is byte 0, byte 1
raw = data[0] | (data[1] << 8);
physical value = raw × factor + offset

Case 2: Start 16, length 16 -> it will occupy bits 16 to 31 which is byte 2, byte 3
raw = data[2] | (data[3] << 8);
physical value = raw × factor + offset

2 - Analysis of DEADBAND_TEST

Honetly, I am not entirely sure of what non-linearity is shown in this test but i am inclined to saying that it is a backlash.

A deadzone is a range of input where nothing happens until you cross a threshold. 
A backlash is like slacking, there is a delay whenever you change directions.

There is a bit of lag at the start after which the y_measured increases linearly till 2.6 when u_commanded drops down to -2.
After this, no matter the change in u_commanded, there is no change in y_measured. 
MeasuredAngle does not immediately begin decreasing, it remains constant for a period of time. This is consistent with backlash

Backlash width = |commanded rate| x (dead time after reversal)
1) dead time from rest - B (one side) = 2 * 1.05 = 2.1 degrees
2) since there is no reversal in y_measured lower bound = 2 * half period = 4 degrees.

backlash width = approx 4 degrees.

### Part C - control design choices

Setpoint(reference) and measurement.
Error term = Setpoint - measurement


error term (e) is passed through the controller to get the control signal (u)

Integral -> remembers past errors
Integral Windup -> when you approach the target but the accumulated integral error causes the controller to overshoot

Anti-windup -> Don't allow the integral term to keep growing when the controller is already saturated
Clamp the values using clamp()

Derivative -> looks at how quickly the error is changing
